02Problem & Objective — Data vs. Static Infrastructure
Implemented
What to say
  • Normally, Terraform scripts hard-code which server runs each service. Moving something between edge and cloud means rewriting scripts by hand.
  • My setup separates the decision (FIGARO) from the build step (Terraform) using one strict JSON contract. Changing topology only swaps the input data file, not the Terraform templates.
Quick answer if asked "Why not just use Ansible or bash?" Terraform tracks state across both AWS and Proxmox—it knows what already exists, creates or deletes VPCs automatically, and lets me tear everything down to $0/hr cleanly.
Technical Reference (Smaller Detail)

Contract models live in src/orchestrator/schema.py (Pydantic v2: PlacementPlan, NodeAllocation, PlacementDecision). Serialized into infra/terraform.tfvars.json matching variable "placement_plan" in infra/main.tf.

infra/main.tf instantiates module "proxmox_nodes" and module "aws_spot_nodes" via Terraform for_each filters. Conditional flag local.has_aws_nodes creates/skips AWS VPC (10.0.0.0/16), public subnet (10.0.1.0/24), IGW, route table, and security group automatically.

05Execution Topologies — 3 Modes & Smart Discovery
Scenarios Validated · Benchmarks Planned
What to say
  • All-Edge: Everything stays on Proxmox ($0 cloud cost, fastest on home Wi-Fi).
  • Hybrid Split: Gateway + Web App stay at the edge, while the AI Receipt Worker scales onto AWS Milan Spot (~$0.005/hr) and the edge gateway forwards scan calls over to it.

06Safeguards & Engineering Trade-offs
Teardown Live-Verified · LXC Live
What to say
  • Budget Breaker: Every AI call logs token spend to Supabase; at $5.00 the API pauses automatically (HTTP 429). I also have a Python monitor that destroys cloud servers if combined cost hits the cap.
  • Auto-Teardown & Idle Timer: Closing the session or shutting down my PC automatically destroys all AWS nodes—even if Proxmox is already powered off. (I ran this live and verified $0 left running in AWS.)
  • QEMU VM vs. LXC Lesson: Running Proxmox inside VMware hid hardware virtualization (VT-x) from normal QEMU VMs. I solved that by switching Proxmox edge to lightweight Linux containers (LXC), which boot fast with Docker inside.
Quick answer if asked "What if your laptop loses Wi-Fi suddenly?" AWS Spot instances run a local cron timer: if they stop getting my heartbeat ping for 15 minutes (or hit 4 hours total), they shut themselves down and terminate automatically.
Technical Reference (Smaller Detail)

1) Budget Guard: supabase/migrations/20261106000001_ai_token_ledger.sql RPC record_gemini_tokens + infra/scripts/cost_guard.py + infra/scripts/terraform_actuator.py (unified to clean both infra/ and infra/terraform/).

2) Lifecycle Safety: scripts/session_guard.py hooks Win32 SetConsoleCtrlHandler (close/logoff/shutdown), resolves cloud IP via get_topology(), pings /api/heartbeat (isolated from /api/health Docker healthchecks in server/src/index.ts), and runs scripts/destroy_all.py (which falls back to -target= AWS destroy when Proxmox is offline). AWS user_data.sh sets TIMEOUT_SEC=900, boot grace 1200, MAX_TTL_SEC=14400 with instance_initiated_shutdown_behavior = "terminate" and /tmp:/tmp bind-mount.

3) Nested Virtualization: QEMU VM 100 hit KVM error (solved via start_vm_no_kvm.py setting kvm=0) and missing boot image; replaced on host with Ubuntu 24.04 LXC Container 101 (192.168.178.128, onboot: 1, systemd quota-pay-compose.service), and infra/modules/proxmox_node/main.tf now defaults to proxmox_virtual_environment_container (virtualization_type = "lxc", nesting = true; validated offline).

08Choosing Where to Run — Proxmox Edge vs. AWS Spot
Solo Now · Shared GPU Team Next
What to say
  • For solo testing right now, Proxmox is easier and cheaper: zero cloud billing while I break and fix containers, fast local restarts, and everything I test in Proxmox LXC carries straight over to the shared GPU server.
  • AWS Spot is better when external access is needed: anyone can reach its public IP over 4G/5G without port-forwarding my home router, though I have to tear it down cleanly after each session because it bills per hour.
  • Once teammates join + I have the GPU server and FIGARO: move the Edge workload onto the shared GPU server (running FIGARO and heavy compute at $0/hr for everyone) and pair it with AWS in Hybrid mode for public team access and shared state.
Quick answer if asked "What changes when teammates start running Terraform with you?" Right now Terraform state sits locally on my laptop; once teammates deploy together, I'll switch terraform.tfstate to a remote backend (like S3) with state locking so two people can't overwrite each other's changes.
Technical Reference (Smaller Detail)

Now (Solo): python scripts/deploy_nodes.py --scenario=all_edge on Proxmox LXC ($0/hr, sub-second local container reload); use --scenario=cloud_burst or hybrid (~$0.005–$0.015/hr Spot) briefly for remote tests, followed by scripts/destroy_all.py.

Next (Team + Powerful GPU Server + FIGARO): Configure Terraform backend "s3" so state is shared cleanly across collaborators, target the shared GPU host via SSH/Docker or Proxmox API with NVIDIA runtime/device passthrough in PlacementPlan, and keep AWS eu-south-1 Spot strictly for elastic burst & external teammate/mobile routing.
